# Revision Plan

*How to use this template: Use this template after any check-in or review that produces substantive feedback (employer meetings, internal team reviews, peer reviews). It's a working document, not a formal submission. Its purpose is to convert act-on feedback into concrete commitments with named owners before anyone starts revising. The team may build several Revision Plans across the project as feedback arrives in batches. Each act-on row eventually becomes a Change Log entry once the revision is complete. The first three rows below are examples showing different feedback types; replace them with your team's own entries.*

## A reminder on triage

Before adding feedback to the plan, sort each item into one of three buckets:

- **Act on.** Feedback that changes what you produce: scope corrections, missing analysis, clear direction changes. *Add to this plan with an owner and target date.*
- **Note.** Context that informs but doesn't change the current work. *Log it in the team's project record so it's available when relevant. It does not belong in this plan.*
- **Set aside.** Scope-adjacent preferences, tentative suggestions, or comments that conflict with the brief. *Document the decision in the team's project record so it's visible as a deliberate choice. It does not belong in this plan.*

A quick test for whether a revision is targeted or structural: if you made the change and didn't tell any of your teammates, would they notice a problem in their own sections? If yes, it's structural and needs to be flagged before work begins.
